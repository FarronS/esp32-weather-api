# Погодный релей

Маленький сервер, который решает главную проблему платы: **медленную и
ненадёжную загрузку погоды на мобильной точке доступа**.

## Зачем он нужен

`api.met.no` отдаёт около **500 КБ JSON по HTTPS**. На ESP32 за телефонной
точкой доступа это занимает 20–40 секунд, а иногда обрывается по таймауту —
именно поэтому данные «долго приходят или не приходят вовсе».

Релей качает этот JSON сам (раз в 10 минут), разбирает его и отдаёт плате
**около 150 байт обычным HTTP без TLS**. Плата получает ответ за доли секунды:

```
ts 1763900000
age 42
now +0 partlycloudy_day
week 25:+2 26:+4 27:+8 28:+6 29:+5 30:+1 01:+1
```

| Строка | Что значит |
|---|---|
| `ts <unix>` | время сервера (UTC). Если часы платы не выставлены — плата возьмёт время отсюда, даже когда NTP заблокирован |
| `age <сек>` | сколько секунд назад сервер обновлял данные с met.no |
| `now <t> <code>` | текущая температура (целое со знаком) и код погоды met.no |
| `week dd:±t ...` | по 7 дням: число месяца и максимум температуры за день |

Если сервер недоступен, плата сама переключается на прямой запрос к
`api.met.no` — то есть работает как раньше, просто медленнее.

## Возможности

- Зависимостей нет — только стандартная библиотека Python 3.8+.
- Фоновое обновление раз в 10 минут (настраивается), с повтором при ошибке
  (30 → 60 → 120 → 240 → 300 секунд).
- Если met.no временно недоступен, сервер продолжает отдавать последние
  удачные данные (поле `age` показывает их возраст).
- Необязательный токен доступа: `?k=TOKEN` или заголовок `X-Token`.
- Эндпоинты: `/` (мини-сайт для телефона), `/weather` (для платы),
  `/weather.json`, `/health`, `/api` (список эндпоинтов текстом).
- **Мини-сайт** на главной странице: те же данные, что на экране платы —
  часы, текущая погода и столбики прогноза на неделю. Открывается с телефона
  по адресу `http://IP-СЕРВЕРА:8080/`, сам обновляется раз в 10 секунд.

## Мини-сайт для телефона

Откройте в браузере телефона (телефон должен быть в той же WiFi-сети):

```
http://192.168.0.112:8080/
```

Там показано ровно то, что видит плата: время (в часовом поясе сервера),
температуру, описание погоды и недельный прогноз столбиками. Страница сама
подтягивает свежие данные каждые 10 секунд, без перезагрузки.

Если на сервере задан `TOKEN`, страница автоматически передаст его — пароль
вводить не нужно. Название города берётся из переменной `CITY`.

## Запуск

```bash
python3 weather_relay.py
```

Проверка:

```bash
curl http://127.0.0.1:8080/weather
curl http://127.0.0.1:8080/health
```

### Настройки (переменные окружения)

| Переменная | По умолчанию | Что это |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `0.0.0.0` | адрес прослушивания |
| `LAT` / `LON` | `54.1961` / `37.6182` | координаты города (Тула) |
| `TZ_OFFSET` | `3` | часовой пояс города (Москва = +3) |
| `CITY` | `Тула` | название города на мини-сайте |
| `REFRESH` | `600` | как часто обновлять данные, секунды |
| `TOKEN` | пусто | если задан — запросы только с `?k=TOKEN` |
| `USER_AGENT` | `heltec-weather-relay/1.0 ...` | чем представляться met.no |
| `METNO_URL` | адрес met.no | подмена источника (для тестов) |

## Развёртывание на сервере с «белым» IP

Подойдёт любой дешёвый VPS (Ubuntu/Debian) — нагрузка минимальная:
один запрос к met.no раз в 10 минут и пара килобайт на ответ плате.

### 1. Скопировать файлы на сервер

```bash
ssh root@ВАШ_IP
mkdir -p /opt/weather-relay
# с локальной машины:
scp server/weather_relay.py root@ВАШ_IP:/opt/weather-relay/
scp server/weather-relay.service root@ВАШ_IP:/etc/systemd/system/
```

### 2. Создать пользователя и запустить службу

```bash
useradd --system --no-create-home --shell /usr/sbin/nologin weather
chown -R weather:weather /opt/weather-relay

systemctl daemon-reload
systemctl enable --now weather-relay
systemctl status weather-relay
journalctl -u weather-relay -f      # логи в реальном времени
```

### 3. Открыть порт

```bash
ufw allow 8080/tcp
```

Проверка снаружи (с телефона или домашнего ПК):

```bash
curl http://ВАШ_IP:8080/weather
```

Должны прийти четыре строки `ts / age / now / week`.
Если не приходит — смотрите firewall у провайдера (Security Group / Firewall
в панели VPS) и `journalctl -u weather-relay`.

### 4. (Необязательно) HTTPS через Caddy

Плата работает по обычному HTTP, сертификат ей не нужен. HTTPS имеет смысл,
если вы хотите закрыть токен от посторонних глаз:

```
# /etc/caddy/Caddyfile
weather.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

После этого порт 8080 можно закрыть (`ufw delete allow 8080/tcp`).

## Docker

```bash
docker build -t weather-relay server/
docker run -d --name weather-relay -p 8080:8080 \
  -e LAT=54.1961 -e LON=37.6182 -e TZ_OFFSET=3 \
  --restart unless-stopped weather-relay
```

## Настройка платы

В `src/secrets.h`:

```cpp
#define RELAY_HOST "203.0.113.10"   // IP или домен сервера
#define RELAY_PORT 8080
#define RELAY_PATH "/weather"
#define RELAY_TOKEN ""              // если на сервере задан TOKEN
```

Если `RELAY_HOST` пустой — релей выключен, плата ходит прямо в met.no.

## Безопасность

- Погодные данные не секретны, но токен по HTTP передаётся открытым текстом.
  Если это важно — поставьте Caddy с HTTPS (см. выше) или задайте `TOKEN`.
- Сервер только читает met.no и отдаёт кэш: он ничего не пишет в интернет,
  не принимает данные от платы и не требует root.

## Частые вопросы

**Нужен ли домен?** Нет, достаточно IP. Домен удобнее, если IP может смениться.

**А если сервер упадёт?** Плата это заметит (таймаут 6 секунд) и сходит в
met.no напрямую — на экране просто данные появятся позже.

**Можно ли запустить дома?** Да, если провайдер даёт «белый» IP или можно
сделать проброс порта. Но домашний IP часто меняется — тогда нужен DDNS
(например, `no-ip`, `duckdns`) и `RELAY_HOST` с доменом вместо IP.
