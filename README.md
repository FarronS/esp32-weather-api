# Погода на OLED — Heltec WiFi LoRa 32 V4

Прошивка для платы **Heltec WiFi LoRa 32 V4** (ESP32-S3): подключается к WiFi,
раз в 15 минут забирает с api.met.no текущую погоду и прогноз на неделю
(одним запросом) и рисует всё на встроенном OLED SSD1306 128x64.

Для быстрой и стабильной загрузки есть **погодный релей** (`server/`) —
маленький сервер, который качает met.no сам и отдаёт плате готовые данные
за доли секунды. Плата умеет работать и без него, но тогда на мобильной
точке доступа загрузка идёт 20–40 секунд.

**Стартовый экран** — часы с датой, а под ними иконка текущей погоды
(солнце, облака, дождь...) и температура на улице. Нажатие кнопки **PRG**
открывает второй экран — **столбики погоды на неделю**: число месяца и
максимальная температура каждого дня. Через 10 секунд без действий экран
сам возвращается к часам. Экран работает на собственной
библиотеке `lib/SmallEPaper` (порт `oled.c` из `SmallePlayer/blink-main`)
со шрифтом 8x8 + кириллица.

## Возможности

- **Часы с погодой** — время крупным шрифтом, дата, иконка текущей погоды и
  температура; время берётся по NTP (часовой пояс настраивается).
- **Анимированные иконки** — у солнца вращаются лучи и «дышит» диск, облако
  покачивается, капли дождя падают с разной скоростью, снежинки летят и
  «виляют», молния вспыхивает, туман плывёт. Кадр обновляется каждые 180 мс.
- **Погода на неделю** — 7 столбиков: число месяца и максимальная температура
  дня в общем масштабе; подписи не наезжают друг на друга.
- **Один экран → второй** — кнопка PRG переключает часы и неделю, экран недели
  сам возвращается к часам через 10 секунд бездействия.
- **Кнопка с первого нажатия** — опрос каждые 20 мс с антидребезгом 25 мс;
  сеть работает в отдельной задаче FreeRTOS, поэтому HTTP-запрос не
  «замораживает» экран и кнопку.
- **Один источник данных** — `api.met.no` (бесплатно, без ключа): один запрос
  отдаёт и текущую погоду, и прогноз на неделю; обновление раз в 15 минут,
  при ошибке — повтор через минуту.
- **Погодный релей (быстрая загрузка)** — `server/weather_relay.py` качает
  met.no сам и отдаёт плате ~150 байт обычным HTTP без TLS. Плата получает
  данные за доли секунды вместо 20–40, даже на мобильной точке доступа;
  если релей недоступен — автоматический откат на прямой met.no.
- **Устойчивость к сети** — переподключение WiFi в фоне, скан эфира и
  диагностика в Serial (уровень сигнала, канал, тип защиты), три NTP-сервера,
  повтор HTTP-запроса, индикатор `!` на экране, если данные устарели.
- **Свой драйвер экрана** — `lib/SmallEPaper` (порт `oled.c` из
  `SmallePlayer/blink-main`) со шрифтом 8x8 и кириллицей, без внешних зависимостей.
- **Настройки без перепрошивки кода** — WiFi в `src/secrets.h` (не попадает в
  git), координаты города и частота обновления — константы в `src/main.cpp`.

## Как собрать на другом ПК

1. Установить **VS Code** + расширение **PlatformIO IDE**
   (или только PlatformIO Core: `pip install platformio`).
2. Открыть папку проекта.
3. Вписать свою WiFi-сеть (см. ниже «Настройки под себя»).
4. Подключить плату USB-кабелем (**с линиями данных**, не «только зарядка»).
5. Собрать и прошить:

```bash
pio run            # собрать
pio run -t upload  # прошить
pio device monitor # смотреть логи (115200)
```

Порт указывать не нужно — PlatformIO находит плату сама.
Если плата не определяется: другой кабель, другой USB-порт, напрямую в корпус ПК.
Плата определяется как `USB-Serial/JTAG` (VID_303A) или `USB-SERIAL CH343` (VID_1A86).

## Настройки под себя

Сначала — WiFi: скопируйте шаблон и впишите свои имя и пароль сети.
`src/secrets.h` добавлен в `.gitignore`, поэтому ваши данные не попадут в git.

```bash
copy src\secrets.example.h src\secrets.h    # Windows
cp src/secrets.example.h src/secrets.h      # Linux / macOS
```

```cpp
// src/secrets.h
#define WIFI_SSID     "МояСеть"
#define WIFI_PASSWORD "мойпароль"
```

| Что | Где |
|---|---|
| WiFi (только 2.4 ГГц) | `src/secrets.h`, `WIFI_SSID` / `WIFI_PASSWORD` |
| Адрес релей-сервера | `src/secrets.h`, `RELAY_HOST` / `RELAY_PORT` (пусто = без релея) |
| Город (координаты) | `src/main.cpp`, `METNO_URL` (`lat`/`lon`, Тула = 54.1961, 37.6182) |
| Частота обновления | `src/main.cpp`, `REFRESH_MS` / `RETRY_MS` |
| Разметка экранов (координаты) | `src/display.cpp`, `displayClock()` / `displayWeek()` |
| Иконки погоды | `src/display.cpp`, `drawIcon()` и `iconForCondition()` |
| Часовой пояс / NTP | `src/main.cpp`, `TZ_OFFSET_SEC` (Тула = UTC+3) |
| Кнопка часы/неделя | `src/main.cpp`, `PRG_BTN` (по умолчанию GPIO0) |
| Пины экрана | `lib/SmallEPaper/src/oled.h` (`-DOLED_SDA=...` в `platformio.ini`) |

## Погодный релей (быстрая загрузка)

Основная причина «данные приходят долго или не приходят» — сам `api.met.no`:
около 500 КБ JSON по HTTPS, что на ESP32 за мобильной точкой доступа занимает
20–40 секунд. Релей из папки `server/` снимает эту проблему:

```
ESP32  --HTTP, ~150 байт-->  релей (ваш сервер с белым IP)  --HTTPS-->  api.met.no
        ответ за доли секунды                                 раз в 10 минут
```

Что делает релей:

- сам качает met.no раз в 10 минут и хранит готовый результат в памяти;
- отдаёт плате компактный текст (~150 байт) обычным HTTP **без TLS**;
- при сбое met.no продолжает отдавать последние удачные данные (`age` — их возраст);
- отдаёт время сервера, так что часы выставляются даже если NTP заблокирован;
- необязательный токен доступа, эндпоинты `/weather`, `/weather.json`, `/health`.

### Быстрый старт на VPS

```bash
# на сервере
mkdir -p /opt/weather-relay
# скопируйте туда server/weather_relay.py и server/weather-relay.service
systemctl daemon-reload
systemctl enable --now weather-relay
ufw allow 8080/tcp
curl http://localhost:8080/weather      # ts / age / now / week
```

Подробно (Docker, HTTPS через Caddy, логи, разбор ошибок) — в
[`server/README.md`](server/README.md).

### Настройка платы

В `src/secrets.h`:

```cpp
#define RELAY_HOST "203.0.113.10"   // IP или домен сервера, "" = ходить в met.no
#define RELAY_PORT 8080
#define RELAY_PATH "/weather"
#define RELAY_TOKEN ""              // если на сервере задан TOKEN
```

Если релей не ответил за 6 секунд, плата автоматически идёт напрямую в
met.no — то есть работает как раньше, просто медленнее.

## Что на экране

Стартовый экран — часы, дата, иконка текущей погоды и температура:

```
        12:34
       17.11.26

    ☀ (иконка)        +5°
```

Время берётся по NTP после подключения к WiFi (пока синхронизации нет,
вместо времени горит `--:--`, а под ним «синхронизация...»). Иконка
и температура приходят с api.met.no и обновляются раз в 15 минут. Если
свежих данных получить не удалось, справа от даты горит `!`.

Иконка погоды **анимирована**: у солнца вращаются лучи, облако покачивается,
капли дождя падают с разной скоростью, снежинки летят и «виляют», молния
вспыхивает, туман плывёт. Кадр перерисовывается каждые 180 мс (`ANIM_FRAME_MS`).
Пока идёт загрузка погоды, часы и кнопка продолжают отвечать: сеть работает
в отдельной задаче FreeRTOS на втором ядре, поэтому HTTP-запрос не «замораживает»
экран.

Нажатие кнопки **PRG** (GPIO0) открывает второй экран — погоду на неделю:

```
 +2       +5       +7       +1       -1       +3       +4
 ████     █████    ██████   █████    ████     █████    █████
 ████     █████    ██████   █████    ████     █████    █████
 ████     █████    ██████   █████    ████     █████    █████
 17       18       19       20       21       22       23
```

Сверху — максимальная температура дня, снизу — число месяца. Высота
столбика показывает ту же температуру в общем масштабе недели; точные
значения всегда написаны цифрами. Данные берутся с api.met.no и
обновляются раз в 15 минут. Повторное нажатие PRG сразу возвращает к часам,
а если кнопку не трогать — экран недели сам сменится часами через 10 секунд.

Кнопка опрашивается каждые 20 мс с антидребезгом 25 мс и срабатывает
с первого нажатия — даже в момент, когда плата качает погоду.
